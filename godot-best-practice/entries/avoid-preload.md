# 禁止 preload

## 核心规则

**永远不要用 `preload()`。** 用 `@export` + 编辑器赋值或 `load()` 替代。

## 为什么

1. **隐式全局加载顺序**：`preload` 在脚本解析阶段执行，在 `_ready`、甚至 `_enter_tree` 之前。被 preload 的资源的依赖链也在同一瞬间拉起，整个加载顺序脱离场景树生命周期，难以预测和控制。

2. **循环依赖**：两个脚本互相 `preload` 对方会触发加载死锁或运行时崩溃。Godot 会尝试打破循环，但行为不可靠、报错信息晦涩。

3. **无法延迟加载**：即使用户从未走到需要该资源的分支，`preload` 也已在启动时把资源钉在内存里。对大型场景/纹理/音频尤其浪费。

4. **重构时静默断裂**：移动或重命名被 preload 的文件后，引用它的脚本不会在编辑器报错（因为路径是硬编码字符串），只会在运行时崩溃。

5. **与场景继承冲突**：在基类脚本里 `preload` 的资源，派生场景无法覆盖；而 `@export` 赋值在 .tscn 里，派生场景可以自由替换。

## 正确替代

| 想做的事 | 正确做法 |
|----------|----------|
| 引用一个场景/脚本/纹理 | `@export` + 编辑器赋值；资源路径写在 .tscn 里，不写在代码里 |
| 运行时按需加载 | `load()`，在需要时调用，可配合缓存 |
| 常量引用（如 Autoload 类型） | 直接 `class_name`，不需要 preload |

## 一句话

**资源引用走 @export 写进 .tscn，运行时按需 load()，绝不 preload。**
