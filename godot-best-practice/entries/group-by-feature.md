# 按功能放在一起

## 约定

目录按功能划分。不要建 `scripts/`、`tscns/`、`assets/` 这类按类型切开的目录。

某个 `.tscn`，以及**只有它会引用**的资源，放进同一个目录。资源包括 `.gd`、子 `.tscn`、音乐、图片。

除**继承场景**外，根脚本是同目录同名 `.gd`（`foo.tscn` → `foo.gd`，用 `[ext_resource]`，根上不要 builtin）。这份 `.gd` 尽量薄，只留对外边界：`signal`、`@export`、少量 public 方法、必要的根级生命周期。场景内具体逻辑放子节点 builtin；builtin 算本场景内部实现，可以访问本 `.tscn` 里含 `_` 前缀在内的私有成员。继承场景的变体根可以继续用 builtin，不强制同名 `.gd`。

只在一个场景里用一次的脚本不要拆成独立 `.gd`。要跨场景或跨节点复用时才拆出去，拆出去之后按普通类边界访问，不依赖别的场景的私有成员。

## 第二次被引用时

新建的东西用到了这份资源，就把它从原来那个 `.tscn` 的目录里拿出来，放到双方都能引用的共同上层目录。

共同上层里东西已经很多时，再在那里开一个公共资产目录，只收该层下跨功能共用的资源，不是按脚本、场景、图片把整个项目切开。
