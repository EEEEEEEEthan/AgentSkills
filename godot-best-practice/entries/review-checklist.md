# Godot 脚本检查清单

编写或审查 GDScript 时可对照：

- [ ] 应尽可能把结构、引用、固定信号与检视器可声明项写进 `.tscn`（节点树、属性、资源引用、`[connection]`）；运行时脚本只做场景表达不了的行为，禁止在脚本里重复搭场景。
- [ ] 所有文本与图片须在场景中预先填好游戏里可能出现的 placeholder 内容，禁止留空或在运行时首次才补默认文案与贴图。
- [ ] 禁止用节点名或路径访问本 tscn 之外的节点，或钻进子 tscn 内部的节点；本子场景内用 `%`，跨场景或跨子场景边界只调对方根上的功能 API。
- [ ] 应按功能把 tscn 与只被它引用的资源放在同一目录（根脚本用同名薄 `.gd`，其余 builtin）；第二处引用上提到共同上层，上层过挤时放进该层公共目录。
- [ ] 成员顺序应为：字段 → 属性 → 方法。
- [ ] 导出属性的 setter 写子节点时，须在同步前 `if not is_node_ready(): await ready`（必要时 `await` 子节点）。
- [ ] 本 tscn 的 unique 子节点应用 `%` 直达；尽可能不用 `@onready`，仅在量到性能问题后再缓存。`%` 只用于本 tscn，跨场景须改走对方根上的功能 API。
- [ ] 子节点访问所属场景根时用 `owner`，不能用 `get_parent()` 硬链。禁止 `get_node` 字符串路径：本场景用 `%`，跨场景用对方根上的公开 API。
- [ ] 不得对场景中必存在的 unique 节点写多余 null 检查。
- [ ] 节点引用应有合适类型提示；要被外场景调用的场景根须写 `class_name`，调用方须直接调方法，不能 `call("方法名")`。
- [ ] 无参、只交出已有节点或算好值的接口应写成属性，不能写成无参方法。
- [ ] 惰性加载资源应采用「成员与 getter 同名」，且每一项只判断自己的成员。
- [ ] 应避免 `call_deferred`。
- [ ] 属性 setter 须同名自赋值，并默认省略显式 `_backing`（仅构造期要绕过 setter 时才保留 `_backing`）。
- [ ] 代码中禁止写注释与空行（说明性文字放在文档与条目里，不留在源码中）。
- [ ] 测试只写关系断言，禁止绝对值断言与过度测试。`A > B`、`A == B` 是关系；无前提的 `A == 100` 是绝对。UI 宽度 `> 100px`、固定坐标、逐像素比对等属于过度测试，外观交给预览脚本人工验收。
- [ ] 不再被引用的废代码（脚本、场景、资源、信号处理、导出字段）应随改动一并清理，禁止长期滞留。
- [ ] UI 须默认只用项目已有的 `Theme` 与 `theme_type_variation`；禁止新建 `Theme` 或 `theme_type_variation`，禁止任何 `theme_override*`，除非用户明确确认。
- [ ] 禁止在代码里写死 UI 的尺寸与位置；固定规格须在 `.tscn` 布局里配置。仅当尺寸或位置会随运行时数据变化时，才允许在脚本里更新。
