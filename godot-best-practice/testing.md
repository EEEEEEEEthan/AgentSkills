# Godot 自动化测试最佳实践

冒烟唯一、专项可复用、时限写在测试代码里、由 Python 出 debug 包再跑。

## 两层

- **冒烟**：唯一。覆盖大部分游戏流程，不是全部。CI 只跑这一条。
- **专项**：很多条，每条覆盖完整 case。开发结束自测时跑。冒烟直接调用其中的某个或某些方法，不把流程再写一遍。

两者都用 GDScript。

## 时间上限

冒烟和专项的入口都在测试代码里写死时间上限。超时即失败。上限取恰好能通过的最短时间。

## 断言

测玩法结果。不规定控件尺寸这类无关细节，除非该尺寸本身就是要验收的行为。

## 启动

Godot 捕获不了脚本报错，编辑器运行和真包也不一致。测试由一个 Python 脚本启动。冒烟和专项都是它的一个选项，一次只跑一个：

```text
python test_runner.py --smoke
python test_runner.py --monkey
```

`--smoke` 是唯一的冒烟。专项的选项名就是测试名，例如专项叫 monkey 就是 `--monkey`。CI 只跑 `--smoke`。

顺序固定：

1. 先 `--import` 一次，让资源跟上当前工程，再把 debug 包导出到临时目录下的 GUID 子目录，避免并发写到同一路径。
2. 用该包跑对应的 GDScript，不在编辑器里跑。
3. 转发 Godot 的 stdout / stderr，供看日志。
4. 输出里一出现错误或警告就立刻停，不等场景自己退出，也不等超时。

模板是同目录的 [test_runner.py](test_runner.py)。拷进项目后改引擎路径、导出预设和 `TESTS`。
